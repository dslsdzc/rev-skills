# 分析契约

分析全流程的三条契约：分析前（上下文清单 + 调查预算）、分析中（数据传递字段）、分析后（复核格式）。所有网关与原子技能执行分析时遵循本契约。

## 一、分析上下文清单（分析前）

分析一个目标（文件 / 函数 / 协议）前，先收集以下上下文再动手：

- 目标标识：路径 / 地址、哈希（sha256）、大小、熵
- 结构信息：架构、格式（PE/ELF/Mach-O/…）、节表摘要、导入导出摘要
- 关联信息：xrefs（引用目标的位置）、目标引用的字符串、caller/callee（函数目标时）
- 已知线索：已命名符号表、已恢复的 struct/类型、本会话已得出的结论（跨环节传递）

收集不到的项目记「未知」，不阻塞开工——但禁止跳过收集直接分析。

## 二、调查预算（分析中）

- 主动申请额外证据（xrefs/反编译/内存读取等工具调用）每目标**不超过 8 次**
- 同参数重复 ≥2 次无新证据 → 换思路；单命令 ≥3 次无进展 → 停下评估
- 证据预载优先：上下文清单一次给足，减少来回调用

## 三、数据契约（分析中，环节间传递）

链式编排（triage → format → 反编译 → 后续环节）的传递字段：

| 字段 | 含义 | 产出环节 |
|---|---|---|
| sha256 | 样本哈希（证据存档键） | re-triage |
| arch / format | 架构与文件格式 | re-triage / re-format-* |
| entropy | 熵值（>7.0 提示加壳/加密） | re-triage |
| sections | 节表摘要（名称/权限/大小） | re-format-* |
| imports / exports | 导入导出摘要 | re-format-* / re-imports |
| strings_refs | 关键字符串引用（地址+内容） | re-triage / re-ghidra |
| base_addr | 加载基址（含偏移换算） | re-format-* / re-ghidra |
| symbols_known | 已命名符号表（会话内累积） | 各环节 |

每个环节输出以上述字段为骨架的结构化摘要（JSON 或表格），下一环节直接消费，不重新扫描。

## 四、复核格式（分析后）

结论交付前做**独立复核**：换视角重读结论与证据（换模型/换工具/间隔后重读均可），逐条核对：

1. 每条结论有对应证据（文件路径 + sha256），无证据的结论标注「推断」
2. 结论与证据矛盾 → 以证据为准，修正结论
3. 标注置信度：高（直接证据）/ 中（间接证据）/ 低（推断）

复核输出格式：

```
结论：<一句话>
证据：<路径 + sha256 / 命令输出位置>
置信度：高 / 中 / 低
未验证项：<复核时无法确认的部分，留空表示无>
```

### 负面结论标准

下「不存在 / 未发现 / 不支持」类结论前，最少做 **3 次不同尝试**（换工具 / 换视角 / 换参数），并在复核输出中列出尝试清单。负面结论的置信度默认「中」，除非尝试清单覆盖了全部合理路径。

### pivot 提示链

分析卡住时按链换路：反调试对抗 → 打补丁/硬件断点 → 混淆 → 动态追踪 → 脱壳；每换一次记录原因（与调查预算联动：同参数重复 ≥2 次即换思路）。
