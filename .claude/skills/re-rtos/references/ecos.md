# eCos：ISR / DSR / thread 三层中断模型

<CORE RULE>
eCos 的中断处理**不是一层**：

```
硬件中断 → ISR → （调度 DSR）→ DSR → 唤醒线程 / 信号条件变量 → 线程
```

于是两个高频误判：

```
ISR 只清状态位就 return        → 别判"中断处理没做实际工作"
某函数无线程入口却被反复调用    → 不一定是 callback 混淆，可能就是 DSR
```
</CORE RULE>

## 一、ISR 与 DSR 的分工

- ISR 返回时若带 **`CYG_ISR_CALL_DSR`** 位，系统会调用关联的 **DSR（Deferred Service Routine）**
- **若调度器未被锁定，DSR 立即运行**；**若被中断的线程恰在内核调用里锁了调度器，DSR 会被推迟到解锁之后**
- 这个推迟正是 DSR 能安全做某些内核调用的原因——**例如 post 一个信号量、signal 一个条件变量**

## 二、同步级别是 API 的属性

每个 API 函数都带一个同步级别：

| 级别 | 谁可以调用 |
|---|---|
| **Thread** | 仅线程代码（如客户端调用驱动） |
| **DSR** | **DSR 或线程**代码 |
| **ISR** | **ISR、DSR 或线程**代码 |

**调用点落在哪一级，决定了哪些 API 是合法的**——这是"为什么这里不用互斥量"的第一解释。

## 三、三种同步机制，各有适用的层

| 机制 | 作用 | 谁能用 |
|---|---|---|
| **与 ISR 同步**（禁中断 `cyg_drv_isr_lock()` / `unlock`） | 阻止临界区内 ISR 运行；SMP 下还需 spinlock | 必须**短**且少用 |
| **与 DSR 同步**（`cyg_drv_dsr_lock()` / `unlock`） | 阻止临界区内 DSR 运行（内核里等价于取调度器锁） | **DSR 与线程可用；ISR 不允许使用** |
| **与线程同步**（互斥量、条件变量） | 线程级阻塞与唤醒 | **只有线程可以 lock 互斥量与 wait 条件变量；DSR 可以 signal 条件变量** |

**数据保护规则按"谁会碰它"分层**：被 ISR 访问的数据在任何层级（**包括 ISR 内部**）都要用 ISR 锁/spinlock 保护；DSR 与线程共享的数据用 DSR 锁；只有线程访问的用互斥量。

## 四、三种典型驱动模型

1. **全部处理放在 ISR**（DSR 只 signal 条件变量唤醒线程）
2. **处理推迟到 DSR**（DSR 可选地 signal 条件变量并解屏蔽中断）
3. **处理推迟到线程**（DSR 只调用条件变量 signal，线程随后获得完整内核设施）

**看到 ISR 极短、真正工作"消失"时，按这三档去找它落到哪一层。**

## 决策树

```
拿到 eCos 目标
├─ 看到一个很短的中断处理函数
│    ├─ 查它是否返回 CYG_ISR_CALL_DSR → 真正工作在 DSR
│    └─ 别判"中断处理什么都没做"
├─ 看到一个没有线程入口却反复执行的函数
│    └─ 可能是 DSR（被 ISR 调度的延迟服务例程），不是 callback 混淆
├─ 判断某个内核调用是否合法
│    ├─ 查该 API 的同步级别（Thread / DSR / ISR）
│    ├─ ISR 里不能做 DSR 级同步；DSR 能 signal 条件变量但不能 wait
│    └─ 互斥量/条件变量等待只能在中断上下文之外
└─ 行为与调度相关
     └─ 记住 DSR 会被调度器锁推迟：时序不能只按"中断发生时刻"推断
```

## 工具与验证

- 分层识别：ISR 的返回值（是否设置 `CYG_ISR_CALL_DSR`）、DSR 注册接口与调用点
- 同步判定：各调用的同步级别（Thread / DSR / ISR）与对应的锁接口
- 驱动模型：判断处理落在 ISR、DSR 还是线程三档中的哪一档
- 验证：能同时说清「处理分布在哪一层 + 共享数据用哪一级保护 + 调度器锁是否影响时序」

## 该平台的坑（汇总）

- **把 ISR 当完整的中断处理**：工作可能在 DSR，甚至在第三个线程里
- **把 DSR 当普通线程回调**：它有自己的同步级别与调度约束，且可能被调度器锁推迟
- **在 ISR 里套用 DSR 级同步的假设**：ISR 不允许使用 DSR 锁
- **以为 DSR 可以像线程一样等待**：DSR 可以 signal 条件变量，但不能 wait
- **按"中断发生时刻"推断时序**：DSR 的运行时机受调度器锁影响
- **按层数相等的假设分配保护机制**：数据该用哪一级锁，取决于谁会访问它（含 ISR 内部）
